# Линия — CRM для студии растяжки

CRM версии 0.2.1 для **одной студии**. Русскоязычный адаптивный интерфейс, роли владельца, администратора и тренера, серверная база данных SQLite. Рабочее название и контакты меняются владельцем в настройках.

## Возможности

- Рабочий стол: аналитика по пяти направлениям, выручка, расходы, долги, клиенты, продажи, занятия и маркетинг.
- Клиенты: таблица с фильтрами и архивом, контактные данные, LTV, заметки, абонементы и история посещений.
- Заявки и собственные воронки; доска задач с ответственными и сроками.
- Расписание: день/неделя, фильтры, создание и отмена занятий, проверка пересечений тренера и зала.
- Записи: проверка вместимости, пересечений клиента, срока абонемента и доступных занятий.
- Абонементы: четыре стартовых тарифа, продажа, срок действия, резервирование и остаток занятий.
- Посещение списывает ровно одно занятие. Повторная отправка отметки не списывает занятие ещё раз. Отмена записи освобождает резерв.
- Финансы: журнал **уже полученных** оплат, фильтры по месяцу и способу оплаты, экспорт CSV. Онлайн-эквайринг не подключён.
- Команда: создание личных учётных записей администраторов и тренеров.
- Настройки: название, адрес, телефон, план выручки. Часовой пояс студии — Москва (Europe/Moscow).
- SQLite, транзакции и внешние ключи; данные сохраняются после перезапуска; резервное копирование работающей базы.

## Запуск

**Windows, без команд:** распакуйте проект и дважды откройте `START-WINDOWS.cmd`.
Если Node.js не установлен или его версия ниже 24, откроется официальный сайт
для установки. После установки снова откройте `START-WINDOWS.cmd`. При первом
запуске скрипт установит зависимости, соберёт интерфейс и откроет браузер после
готовности сервера. Окно запуска должно оставаться открытым. Пошаговая инструкция
находится в файле `КАК ЗАПУСТИТЬ.txt`.

Требуется **Node.js 24+** с встроенным `node:sqlite` и npm. PostgreSQL, Docker и внешние API не нужны.

```bash
cd /workspace/arsen199999
npm ci --cache /tmp/linia-npm-cache --no-audit --no-fund
npm run build
npm start
```

Сервер слушает локальный порт **3000**. Он отдаёт API и собранный интерфейс с одного origin. По умолчанию привязан к `127.0.0.1`. В облачной среде отображение приложения зависит от доступного в продукте механизма доступа к этому порту.

Для разработки:

```bash
npm run dev
```

Команда запускает API на порту 3000 и Vite на порту 5173 с прокси `/api`. Остановите предыдущий `npm start`, если порт 3000 занят. Изменения React и серверных файлов подхватываются автоматически.

## Демонстрационная студия

При первом запуске по умолчанию создаются вымышленные клиенты, занятия, абонементы и оплаты. На странице входа есть кнопки для трёх ролей. Демовход открыт намеренно; используйте этот режим только для знакомства с CRM.

Даты демонстрационных занятий привязаны к первому запуску. Повторные запуски сохраняют данные и не добавляют новые копии демонстрационных записей. Тесты используют отдельные временные базы и не изменяют вашу студию.

## Чистая студия и личные аккаунты

Для работы с настоящими клиентами запустите отдельную базу **без демовхода**:

```bash
DEMO_MODE=0 DATABASE_PATH=./data/live.sqlite npm start
```

Перед этим остановите другой экземпляр на том же порту. Первый экран предложит создать владельца и задать название студии. Выполняйте первоначальную настройку до открытия доступа другим людям. Пароль — минимум 10 символов. Затем добавьте тренеров и администраторов в разделе «Команда».

`DEMO_MODE` применяется только при создании новой базы. Изменение переменной не очищает уже существующую демонстрационную базу и не отключает в ней демовход. Отдельный путь сохраняет демобазу и создаёт независимую рабочую студию.

| Роль          | Доступ                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------- |
| Владелец      | Все разделы, настройки и создание сотрудников                                                       |
| Администратор | Клиенты, расписание, записи, абонементы, оплаты; просмотр тренеров                                  |
| Тренер        | Свои занятия и их участники, отметка посещений; без финансов, абонементов и управления сотрудниками |

Ограничения проверяются сервером. Пароли хешируются scrypt с индивидуальной солью. Сессии используют случайные токены, `HttpOnly`/`SameSite=Strict` cookies и срок 12 часов. В базе хранится хеш токена. Есть ограничение попыток входа и защита от записи с чужого origin.

## Конфигурация

Пример — `.env.example`. Для загрузки собственного файла настроек используйте:

```bash
node --env-file=.env server/index.mjs
```

| Переменная      | По умолчанию           | Назначение                                                         |
| --------------- | ---------------------- | ------------------------------------------------------------------ |
| `HOST`          | `127.0.0.1`            | Интерфейс для сервера                                              |
| `PORT`          | `3000`                 | Порт HTTP                                                          |
| `DATABASE_PATH` | `./data/studio.sqlite` | Путь к SQLite относительно рабочей директории                      |
| `DEMO_MODE`     | `1`                    | Демоданные и демовход при создании новой базы; `0` — чистая студия |
| `COOKIE_SECURE` | `0`                    | `1` для cookies только через HTTPS                                 |

Для размещения вне локальной машины нужны HTTPS, постоянный диск для базы и регулярные резервные копии. Обратный прокси должен сохранять исходный заголовок `Host`; интерфейс и `/api` обслуживаются на одном домене. `COOKIE_SECURE=1` включается вместе с HTTPS. Сеть и публикация приложения в этой версии не настроены автоматически.

## Проверки

```bash
npm test
npm run build
npm run test:ui
```

- Серверные тесты: авторизация, роли, продажа и её атомарность, нормализация телефонов, пересечения, вместимость, резервирование, посещения, отмены, сохранение SQLite и защита от стороннего origin.
- Браузерный сценарий: создание клиента → абонемент → занятие → запись → посещение; затем финансы, CSV, настройки, новый сотрудник и его вход, мобильная навигация.
- Для браузерного сценария нужен Chromium. Скрипт использует `/usr/bin/chromium`, если он установлен, либо браузер Playwright. Другой путь задаётся `CHROMIUM_PATH`. На обычной машине можно установить браузер командой `npx playwright install chromium`.
- Скриншоты проверок сохраняются в `test-results/`, который исключён из Git.

## Резервное копирование

```bash
npm run db:backup
# Для другой базы:
DATABASE_PATH=./data/live.sqlite npm run db:backup
```

Команда использует SQLite Backup API, корректно учитывает WAL и проверяет целостность копии. Копии сохраняются в `data/backups/`. Переносите их на независимый носитель. Они содержат данные клиентов и сотрудников и требуют такого же контроля доступа, как основная база.

Для восстановления остановите приложение, сохраните текущую базу вместе с её WAL-файлами и укажите `DATABASE_PATH` на **новую рабочую копию** проверенного резервного файла. Это позволяет сохранить исходную базу до проверки восстановления.

## Правила учёта и границы первой версии

Продажа сразу создаёт оплаченный абонемент по цене тарифа. Срок считается включительно от выбранной даты. Запись резервирует занятие; списание происходит при отметке посещения. Необработанная запись остаётся зарезервированной, в том числе за прошлый день: администратору нужно отметить посещение либо отменить запись. Будущие посещения отмечать нельзя. Посещение можно отметить за текущий или прошедший день.

CRM пока не включает онлайн-запись клиентов, сообщения по SMS/мессенджерам, банковский эквайринг, фискализацию, возвраты, заморозку абонементов, повторяющиеся занятия, расчёт зарплаты, восстановление пароля по email и удаление аккаунтов. Это следующий этап развития. Начальные тарифы задаются в `server/db.mjs`; редактирование тарифов через интерфейс пока не добавлено.

## Структура

- `src/` — React, TypeScript, интерфейс и адаптивные стили; шрифт Manrope хранится в сборке.
- `server/db.mjs` — схема SQLite, демонстрационные данные и транзакции.
- `server/app.mjs` — Express API, сессии, роли и проверки бизнес-правил.
- `server/index.mjs` — запуск и корректное завершение сервера.
- `scripts/` — разработка, браузерная проверка и резервное копирование.
- `tests/` — интеграционные тесты API и сохранности базы.

Облачные задачи уже изолированы. Используйте существующий checkout; отдельный Git worktree нужен только по явной просьбе.

- Клиенты: таблица, выбор столбцов, сортировка, страницы, фильтры по полу, возрасту, источнику, менеджеру, городу, тегам, регистрации, посещению, LTV и абонементу. Архив обратим и не отменяет покупки или посещения.

- Боковое меню «График и расписание»: расписание, дежурства, занятость тренеров и залов по занятиям, журнал записей. Дежурства создаются отдельно с проверкой пересечений.
- Услуги и товары, частичная оплата абонемента или другой покупки, погашение долга, журнал расходов. Финансовые и коммерческие разделы доступны владельцу и администратору.

### Как считаются показатели

Часовой пояс — Москва. Выручка означает полученные оплаты в периоде; создание продажи без оплаты выручку не увеличивает. Долги вычисляются по продажам и оплатам на дату окончания отчёта (не позднее сегодня). Средний чек считается по полной стоимости продаж, а не по числу частичных оплат. Суммы вводятся в целых рублях.

LTV — фактически полученная выручка за всю историю до даты отчёта на одного зарегистрированного клиента, включая клиентов без покупок. Возраст учитывается только при заполненной дате рождения; пол без заполнения остаётся неизвестным. Процент продления — доля завершившихся в периоде абонементов, для которых куплен следующий с началом не позже 30 дней после окончания; покупки после даты отчёта не учитываются. Исторические изменения профиля клиента отдельно не версионируются.

Заполненность включает будущие неотменённые занятия и записи в выбранном периоде. Доходимость учитывает только уже завершившиеся занятия. Посещения появляются после отметки тренера или администратора. Расчёты не включают отменённые занятия.

Маркетинг: заявки группируются по дате создания. При продаже источник и последняя связанная заявка фиксируются в продаже. Одна продажа относится к одной заявке; повторные заявки того же клиента не получают одну оплату несколько раз. Конверсия считается по наличию оплаты до даты отчёта, выручка канала — по датам оплат внутри периода. Старые продажи сохраняют источник из карточки клиента на момент миграции. Вымышленные заявки для старых клиентов не создаются.

Клиентское мобильное приложение, отслеживание его установок, рекламные интеграции, прогноз продления, онлайн-оплата, возвраты и автоматические сообщения не подключены. Установки приложения показываются как «Не подключено». Произвольные поля со скриншотов внешней CRM без источника данных не заполняются вымышленными значениями.

### Установка обновления Windows с сохранением студии

1. Закройте окно запуска работающей CRM.
2. Распакуйте новую версию в отдельную папку.
3. Откройте `UPDATE-WINDOWS.cmd` из новой папки.
4. Выберите прежнюю папку CRM (с `START-WINDOWS.cmd` и `data`).
5. Дождитесь завершения, затем откройте `START-WINDOWS.cmd` в прежней папке.

Полная инструкция — `КАК ОБНОВИТЬ.txt`. Программа сначала устанавливает зависимости и собирает обновление отдельно, затем проверяет резервные копии SQLite. Пользовательские `data` и `.env` остаются на месте. Копия предыдущего кода, зависимостей и баз сохраняется в `update-backups`. При ошибке замены файлов восстанавливается предыдущий код. Перед первым изменением схемы SQLite дополнительно выполняется `VACUUM INTO` рядом с базой в `backups`, а миграция выполняется одной транзакцией. Старая таблица `payments` остаётся нетронутой; после миграции приложение использует `sales` и `receipts`.

Внешний `DATABASE_PATH` и нестандартный `PORT` необходимо сохранить в `.env` прежней студии; Windows-запуск теперь читает `.env`. Скрипт проверяет, что порт студии свободен, но приложение нельзя запускать параллельно с обновлением. Первоначальный режим базы (демо или рабочий) сохраняется. Установка обновления не отключает демовход у демонстрационной базы.

Проверки обновления охватывают сохранение пользовательской базы и `.env`, резервное копирование, откат файлов при ошибке и миграцию версии 1. Диалог выбора папки и запуск `.cmd` требуют Windows; в облаке проверяется общий механизм установки и запуска на Linux.

### Исправление обновлятора 0.2.1 для Windows

Обновлятор оставляет папку `tests` на месте и больше не переименовывает каталоги
работающей установки. Сначала он сохраняет все предыдущие файлы в резервную копию,
затем заменяет содержимое каталогов. Это устраняет ошибку `EPERM ... rename ... tests`,
возникшую при блокировке каталога в Windows. Отдельные файлы по-прежнему должны быть
доступны для записи; закрывайте CRM перед обновлением. Если восстановление файлов
после ошибки тоже заблокировано, программа сообщает об этом и указывает резервную
копию, вместо сообщения об успешном восстановлении.

На Windows npm запускается через Node без передачи аргументов в оболочку, чтобы
не вызывать предупреждение `DEP0190`. Повторная попытка обновления выполняется из
нового архива; вручную переносить или удалять папку `data` не нужно.
